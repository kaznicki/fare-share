## Color

Two-accent system — intentional by design (D-01 through D-04):

| Role | Value | Tailwind token | Usage |
|------|-------|----------------|-------|
| Dominant (60%) | `#ffffff` | `bg-white` | Page backgrounds, card surfaces |
| Secondary (30%) | `#f9fafb` | `bg-gray-50` | Hover states, subtle backgrounds |
| Accent A — Financial (10% reserved) | `#4f46e5` | `indigo-600` | Money moments and session-entry only |
| Accent B — Action (10% reserved) | `#2563eb` | `blue-600` | Action buttons only |
| Destructive | `#dc2626` | `red-600` | Error banners only (no destructive actions in this phase) |

**Accent A (indigo-600) reserved for:**
- `SummaryScreen` "Total owed" label and value (financial moment)
- `ShareScreen` "Join as host" button (session-entry moment)
- `UnclaimedModal` "I'm done" button (session-finalize moment)
- `SessionRoom` "Finalize" button (session-finalize moment)

**Accent B (blue-600) reserved for:**
- `CameraCapture` "Take Photo" and "Use Photo" buttons (action)
- `OcrReview` "Create Session" button (action)
- `JoinForm` "Join" submit button (action)
- `TaxTipFields` active tip preset button (`bg-blue-600`) (active state indicator)

**Phase 8 color changes:**
- D-04 audit: verify every component follows the split. Fix any stray colors found — do not introduce a third accent.
- No new colors. No color removals beyond fixing stray violations.

**Rule:** if an element is money-related or marks a session transition, it is indigo. If it is a host/user action button, it is blue. Semantic colors (green/gray for claim states in `ClaimableItem.tsx`) are not accent and must not be changed.

## Component Specifications

### Fix 1 — Font (D-05)

**File:** `app/globals.css`

Remove the `body { font-family: Arial, Helvetica, sans-serif; }` rule entirely. The `@theme` block already maps `--font-sans: var(--font-geist-sans)`, so Geist Sans activates automatically.

Before:
```css
body {
  background: var(--background);
  color: var(--foreground);
  font-family: Arial, Helvetica, sans-serif;
}
```

After:
```css
body {
  background: var(--background);
  color: var(--foreground);
}
```

### Fix 2 — OcrReview heading (D-06)

**File:** `components/host/OcrReview.tsx` line 53

Change `text-xl font-semibold` to `text-2xl font-bold`:

```tsx
// Before
<h1 className="text-xl font-semibold mb-4">Review Receipt</h1>

// After
<h1 className="text-2xl font-bold mb-4">Review Receipt</h1>
```

### Fix 3 — SummaryScreen card shadow (D-07)

**File:** `components/session/SummaryScreen.tsx` line 24

Add `shadow-md` to the personal breakdown card:

```tsx
// Before
<div className="bg-white border border-gray-200 rounded-2xl p-6">

// After
<div className="bg-white border border-gray-200 rounded-2xl p-6 shadow-md">
```

Pattern: `bg-white rounded-2xl shadow-md` — already used in `JoinForm.tsx` and `ShareScreen.tsx`.

### Fix 4 — OcrReview sticky footer card wrapper (D-08)

**File:** `components/host/OcrReview.tsx` lines 103–121

The existing `<div className="px-4 pb-4 pt-2 bg-white">` wrapper gets replaced with the card pattern. The `TaxTipFields` component plus the "Your name" input plus the "Create Session" button are all wrapped together:

```tsx
// Before
<div className="px-4 pb-4 pt-2 bg-white">
  ...
</div>

// After — card wrapper with shadow
<div className="px-4 pb-4 pt-2 bg-white rounded-2xl shadow-md">
  ...
</div>
```

Note: the scrolling item list above the footer stays flat (no shadow). Only the pinned footer gets the card treatment.

## Trust Boundaries

|----------|-------------|
| SummaryScreen button → page.tsx onUnfinalize → REST POST | Host-initiated action; REST endpoint validates host identity server-side (Plan 02) |
| WebSocket snapshot → SessionRoom onUnfinalized → setScreen | Server-broadcast state change; no untrusted client input crosses this boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-03-01 | Elevation of Privilege | page.tsx REST call to /api/sessions/[id]/unfinalize | mitigate | Body sends `hostName: participantName` — the REST route (Plan 02) validates this against session.hostName and returns 403 if mismatch; non-hosts cannot trigger unfinalize via this path |
| T-07-03-02 | Tampering | SessionRoom prevFinalizedRef transition detection | accept | The transition fires `onUnfinalized` only on `prevFinalizedRef.current === true && msg.data.finalized === false`; initial mount (false→false) does not fire; spoofed WS messages would need to reach server.ts which applies the host guard before broadcasting |
| T-07-03-03 | Denial of Service | SessionRoom always-mounted pattern | accept | One additional DOM subtree (display:none) per participant session; negligible memory impact at single-session scale |
</threat_model>
